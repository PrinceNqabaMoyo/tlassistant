Design Principles

1Deterministic systems always win — procedure tracker, cell marker, rubric detector are sources of truth. No LLM output may override them.
2The .md session file is for audit only — never the primary data pipeline, never sent to teachers/parents.
3External reports (teacher, parent) are always PDF — no raw JSON, field names, or system language.
4LLM reads stripped-down Firestore JSON profile, never raw .md files or full Firestore documents.
5Dual-layer data: session_index Firestore document for deterministic computation; .md file for human-readable audit.
6Empty cells never earn marks. Filling a must_be_empty cell earns a deduction.
7Every archetype has a fixed, reproducible marking_schema defined at generator time.
8No freeform chat — declarative clickables over prompt engineering. The UI diverges: zero-setup highway for students, high-agency cockpit for teachers.
9SimuLearn seeds are pre-decided per archetype by the developer — all users see the same canonical simulation.
10Gamification never compromises academic quality — badges earned through demonstrated understanding, not activity volume.
11The dashboard is a retention hook — profile data must be pipeline-ready from Phase D1.
12Landing page changes require explicit owner approval before implementation.
13No file should exceed 2000 lines — modularise before a file reaches this limit.
14Always backup App.jsx before editing it.
15Comma decimal separator throughout (SA/CAPS standard): LaTeX uses {,}.
16Generator Contract: All generators must emit term metadata (1..4), deconstructible elementary sub-drills, standardized misconception tags, and teacher-editable marking schemas.
17Exam-on-Demand with Calendar Pacing: Students can trigger full mock exams at any time, bounded by current school term (term <= selected_term) with post-exam triage debriefs.
18Examining Body Trademark Policy: Never use IEB, SACAI, DBE, or NSC trademarks in marketing. Use universal public-domain statements: '100% Aligned with South African Curriculum Standards (CAPS)'.
19Production Scalability at 10k Users: FastAPI ASGI architecture with asyncio.to_thread sandboxing for SymPy (2.5s timeout), client-side batched telemetry buffers, and single mastery_snapshot document reads (reducing Firestore reads by 97.5%).
20LLM Infrastructure & Economics: Standardize on Google Gemini 2.0 Flash via provider abstraction for sub-dollar monthly costs at scale, maintaining 100% zero-LLM deterministic Python for Standard tier question generation and marking.
21Cyclomatic Complexity Standards: Enforce maximum CC of 12 for generator code via radon/CI gates, and derive mathematical procedural_complexity_score (1..10) directly from canonical solution graph branch points.
22Anti-Erosion Architectural Governance: Enforce 5-tier automated pipeline (AST purity linter banning LLM imports in generators, pytest 6-pillar contract suite, seed determinism tests, radon CC gates, and manifest synchronization) to prevent architecture drift during future development.
23Zero Freeform Socratic Chat: All Socratic tutor assistance is 100% declarative and driven by dynamic 1-tap suggestion chips derived from detected misconception tags, with Socratic Shield output sanitization and a 3-strike circuit breaker to SimuLearn.
24POPIA-Compliant Localization & Zero-GPS Architecture: Strict prohibition of real-time device GPS polling or spatial Maps LLMs (protecting minors under POPIA Sec 35). Regionalization is achieved via 1-tap onboarding dropdowns (Province/School) and passive edge IP headers, while ad targeting is managed externally in Meta/Google Ads Manager and amplified by the WhatsApp School-Cluster viral loop.
25Curriculum Source Precedence: curriculum_docs_auto/ takes primary priority for pacing, authentic exam mark allocations, term scheduling, and diagram vision annotations, and must be used in conjunction with manually typed curriculum_docs/ when authoring and calibrating generators.
26Horizontal Curriculum Provision & Diagnostic Adaptive Regression: Topics are sliced horizontally into atomic subskill parameters with strict grade-ceiling gating. Learners enter via a 3-question diagnostic benchmark ('the question is waiting'). Failures on compound questions trigger automated adaptive regression into elementary sub-drills (mode='elementary_<subskill>') and prerequisite booster registries to rebuild schema before advancing.
27Curriculum Provision & Memory-Decayed BKT Guardrails: The system tracks subskill mastery with continuous Ebbinghaus time decay (P(L, Δt)), flagging topics for a 2-question refresher when dropping below 70%. Post-exam triage executes a 3-step cognitive repair sequence (Cognitive Conflict Probe → SimuLearn Micro-Replay → Isomorphic Pair). To prevent cognitive degradation, a 45-minute deliberate practice circuit breaker triggers recovery prompts, while teacher homework assignments execute via an Express Priority Lane with dual-ledger telemetry recording, and offline mobile sessions sync atomically via IndexedDB buffers.

1STEP 1 — SESSION START: Read fundile-architecture.json in full before writing any code. This file is the single source of truth for what is built, what is planned, and what the system constraints are. Do not ask the owner to explain the architecture.
2STEP 2 — DURING SESSION: Whenever you build, partially build, or change the status of any layer, service, API route, frontend component, Firestore collection, or generator — update fundile-architecture.json immediately. Change the 'status' field from 'planned' to 'partial' or 'built'. Move items between 'built' and 'planned' arrays. Update 'lastUpdated'.
3STEP 3 — WHAT TRIGGERS A JSON UPDATE: New service created → add to backendServices.built. New route added → add to apiRoutes.built. Generator completed → move from generators.planned to generators.built. Firestore collection created → update firestoreCollections. New design principle agreed with owner → append to designPrinciples. Open question resolved → remove from openQuestions.
4STEP 4 — WHAT DOES NOT TRIGGER A JSON UPDATE: Internal function refactors. Bug fixes. Comment additions. Variable renames. Test additions. File moves within a service that does not change its interface.
5STEP 5 — SESSION END: After all code changes are complete and before ending the session, run this command from the project root: python generate_architecture_html.py — This regenerates fundile-architecture.html from the updated JSON. Always run this last.
6STEP 6 — NEVER EDIT HTML DIRECTLY: fundile-architecture.html is a generated file. Any direct edit will be overwritten by the next script run. All changes go through fundile-architecture.json.
